Abstract

Current 3D navigation agents use fixed-resolution images, forcing a trade-off between computational cost and perceptual detail: low resolution limits object recognition, while high resolution is expensive to process at every step. One solution to this problem is providing an agent with the capacity of modulating the resolution of its vision, giving it the possibility to navigate at low cost and identify object relactively accuratly.

To prove the efficacy of this solution, we consider a RL 3D navigation task in AI2-THOR where an agent must reach and center a target object in apartment scenes. The agent performs navigation actions plus a special sensing action that temporarily increases observation resolution under a limited perceptual budget. Observations include RGB input, GPS+Compass, and past actions, encoded with a memory-based model (LSTM). The reward encourages successful goal completion and efficient navigation while penalizing time, failures, and unnecessary high-resolution sensing.

I. Introduction

Object search in 3D scenes is a common task in embodied AI. An agent must move through an environment, interpret images, and decide where to go in order to find an object. In this project, we consider a setting where perception itself is an active and constrained process. The agent initially observes the scene at low resolution and may choose to acquire additional information by increasing the resolution of its current view before acting.

This project is motivated by two main observations. First, biological vision operates under similar constraints: perception is limited in resolution and attention is required to focus on relevant parts of the scene, which can be implicitly modeled through dynamic resolution. Second, selectively acquiring information can be more efficient than processing high-resolution images at every step, and allows the agent to adapt its perception to different stages of the task, such as navigation versus object recognition.

Most 3D navigation agents are trained on fixed-resolution images, but this setting may not be suited to all aspects of the task. Prior work by Atanov [2] has shown that agents can perform simple navigation tasks even with very low-resolution observations. However, these agents may struggle in more complex environments, for example when contrast is low or when objects are numerous, complex, or small. Navigation can be achieved with low visual information, but object recognition should require more details to be precise. Moreover, continuously processing high resolution images is computationally heavy and unnecessary in many situations. So there is a gap to bridge to have a model effective in both tasks and low cost. We therefore explored a similar setting by introducing dynamic resolution, allowing the agent to improve its camera resolution over time when it chooses to focus on the scene currently in vision. This is also a more natural approach to vision since it implicitly reflects attention.

Many real-world systems operate under constraints on sensing and computation. A realistic agent should not rely on constant access to dense visual information, but instead learn when additional information is worth acquiring. This motivates dynamic-resolution perception for several reasons:

  • More realistic perception modeling. The progressive observation model captures the fact that perception is limited in resolution and constrained by time or energy, making the agent's vision closer to biological and real-world sensing.
  • Computational efficiency. By learning when high-resolution observations are truly necessary, the agent can reduce the number of expensive sensing and processing operations.
  • Adaptive attention. The sensing action gives the agent a way to actively decide when to focus on visual details, instead of processing every observation with the same level of precision.
  • Robustness in complex environments. Low-resolution models may work well in simple settings, but they can struggle when objects are small, visually similar, partially occluded, or placed in cluttered scenes. Dynamic resolution offers a trade-off between low-cost navigation and detailed object recognition.
  • Better use of limited resources. In real robotic systems, sensing, memory, bandwidth, and computation are limited. An agent that learns when to acquire more information can operate more efficiently under such constraints.

II. Related Works

This work is largely inspired by the work of Atanov et al. [2], which studies how far vision-based agents can go with extremely low-resolution visual sensors. Their work shows that simple photoreceptor-like sensors can still provide enough information to solve several active vision tasks, including visual navigation. Our project follows the same general motivation: high-resolution visual input is not always necessary for embodied decision-making.

The main difference is that we do not use a fixed low-resolution camera. Instead, we introduce dynamic resolution: the agent starts from degraded observations and can decide when to increase the resolution of its current view. We also study a target-object navigation task, where the agent must both navigate through the environment and identify a target object.

Our work is also related to Dynamic Resolution Network by Zhu et al. [3]. In that work, a lightweight resolution predictor selects the lowest input resolution that still allows a CNN to classify an image correctly. This supports the idea that full resolution is not always required in vision models. However, their method is designed for image classification, while our project applies dynamic resolution to a sequential reinforcement-learning setting.

Navigation and object-recognition tasks are common in reinforcement learning, but to our knowledge, there is no directly comparable setup that introduces dynamic resolution as an action learned by an embodied RL agent.

III. Methodology

Task and environment

We formulate the problem as an embodied object-navigation task in AI2-THOR. Each episode takes place in an apartment scene. At the beginning of the episode, the agent is placed at an initial position and receives a target object category. The goal is to navigate through the scene and reach the target object within a limited number of steps.

The environment follows a reinforcement-learning interface. At each timestep, the agent receives an observation, selects an action, and receives a reward. The action space of the adaptive agent includes four movement actions, two rotation actions, a DONE action, and a SENSE action. Movement actions displace the agent by 25 cm, while rotations turn the agent by 45 degrees. The DONE action terminates the episode. The SENSE action improves the resolution of the current visual observation without moving the agent.

This setup is motivated by the fact that navigation and object recognition do not require the same level of visual detail. Coarse visual information can be enough to move through a scene, while recognizing a target object may require sharper observations. Our goal is therefore to test whether an agent can learn when high-resolution perception is useful, instead of processing high-resolution images at every step.

Dynamic-resolution perception

The central component of our method is a dynamic-resolution observation model. The agent does not always receive the original RGB image. Instead, it starts from a degraded observation and can spend a limited sensing budget to improve the resolution of its current view.

Resolution is represented by a downgrade level. Level 0 corresponds to the original image. Higher levels correspond to stronger degradation. When the agent uses SENSE, the downgrade level is reduced by one, making the image sharper. When the agent moves, the observation is reset to the initial low-resolution level. This forces the policy to decide whether visual detail is worth its sensing cost.

The image degradation is implemented directly on the RGB frame. The original image is resized to 224 × 224. For a downgrade level \(l\), the image is divided into non-overlapping blocks of size \(2^l \times 2^l\). Each block is replaced by the average value of its pixels. The resulting low-resolution image is then upsampled back to 224 × 224 using nearest-neighbor interpolation:

\[ I_l = \operatorname{Upsample} \left( \operatorname{BlockAvg}_{2^l \times 2^l}(I) \right) \]

where \(I\) is the original RGB image and \(I_l\) is the degraded observation at resolution level \(l\). This keeps the neural network input size fixed while changing the amount of visual information available to the agent.

Observations and target conditioning

The policy receives both visual and auxiliary information. The visual input is the current degraded RGB image. The auxiliary input contains the normalized GPS position of the agent, compass information, the previous action, the current resolution level, the remaining sensing budget, and the target object index.

Target conditioning is necessary because the agent must know which object it is looking for. In the current setup, the target object is sampled from a restricted vocabulary containing Mug and Bowl. The target index is converted into a learned embedding before being passed to the policy. This allows the same policy to be trained on multiple target categories instead of learning a separate policy for each object.

Policy architecture

The policy follows a recurrent actor-critic architecture. The RGB image is first encoded with a frozen DINOv2 visual encoder. In the main adaptive setup, we use DINOv2-base, which outputs a 768-dimensional visual feature vector. This feature vector is concatenated with the auxiliary features and the learned target-object embedding.

The concatenated representation is then passed to an LSTM. The LSTM gives the agent memory across timesteps, which is important because the task is partially observable. A single low-resolution frame may not contain enough information to identify the target object or to infer where the agent has already been. The recurrent state allows the agent to integrate information over previous observations, actions, positions, and sensing decisions.

The LSTM output is passed to two heads. The policy head outputs a probability distribution over the action space. The value head estimates the expected future return from the current state. These two outputs are trained jointly using Proximal Policy Optimization.

Reward function

The reward is designed to encourage the agent to reach the target efficiently while penalizing unnecessary actions and unnecessary high-resolution sensing. The reward contains a distance-progress term, action costs, a terminal success reward, a penalty for stopping too early, and a timeout penalty.

At each timestep, we compute a progress reward:

\[ r_t^{\mathrm{progress}} = \alpha(d_{t-1} - d_t) \]

where \(d_{t-1}\) is the previous distance to the target, \(d_t\) is the current distance to the target, and \(\alpha\) is the distance shaping coefficient. If the agent moves closer to the target, then \(d_{t-1} - d_t > 0\), so the reward is positive. If the agent moves away from the target, the reward is negative.

The full reward can be summarized as:

\[ \begin{aligned} r_t = &\ \alpha(d_{t-1} - d_t) + b_{\mathrm{vis}}\mathbf{1}_{\mathrm{first\ visible}} \\ &- c_{\mathrm{step}}\mathbf{1}_{\mathrm{valid\ nav}} - c_{\mathrm{bump}}\mathbf{1}_{\mathrm{failed\ action}} \\ &- c_{\mathrm{sense}}\mathbf{1}_{\mathrm{valid\ SENSE}} - c_{\mathrm{over}}\mathbf{1}_{\mathrm{invalid\ SENSE}} \\ &+ R_{\mathrm{success}}\mathbf{1}_{\mathrm{DONE\ and\ success}} \\ &- c_{\mathrm{done}}\rho_t\mathbf{1}_{\mathrm{DONE\ and\ failure}} \\ &- c_{\mathrm{fail}}\mathbf{1}_{\mathrm{timeout\ and\ failure}} . \end{aligned} \]

The wrong-DONE penalty is scaled by the distance to the target:

\[ \rho_t = \min \left( \frac{\max(d_t - d_{\mathrm{success}}, 0)} {d_{\mathrm{success}}}, 3 \right) \]

where \(d_{\mathrm{success}}\) is the success-distance threshold. This means that stopping far from the target is penalized more than stopping slightly outside the success radius. In the current implementation, success is defined by distance to the target. The visibility condition is not part of the success check, but the first time the target becomes visible can still provide an additional bonus.

In the main adaptive setup, we use: \(R_{\mathrm{success}} = 10.0\), \(c_{\mathrm{step}} = 0.01\), \(c_{\mathrm{sense}} = 0.01\), \(c_{\mathrm{over}} = 0.0\), \(c_{\mathrm{bump}} = 0.05\), \(c_{\mathrm{done}} = 2.0\), \(c_{\mathrm{fail}} = 1.0\), \(b_{\mathrm{vis}} = 0.5\), \(\alpha = 0.5\), and \(d_{\mathrm{success}} = 1.5\) m.

The sensing penalty is central to the project. If it is too low, the agent may overuse high-resolution observations. If it is too high, the agent may avoid sensing entirely. The adaptive-resolution problem therefore depends on balancing task performance against perception cost.

Proof of concept: high-resolution baseline

Before training the full adaptive-resolution agent, we implemented a high-resolution proof of concept. The goal of this PoC is to verify that the environment, reward function, visual encoder, recurrent policy, and PPO loop can learn a simplified version of the task. This is an important sanity check: if a high-resolution agent cannot learn the simplified navigation problem, then failures in the adaptive setup cannot be attributed only to the difficulty of learning when to sense.

In the PoC, the agent always receives full-resolution observations. The SENSE action is disabled, the sensing budget is set to zero, and the action space is reduced to four actions: MoveAhead, RotateLeft, RotateRight, and DONE. The environment uses 224 × 224 observations, a maximum episode length of 50 steps, random target sampling between Mug and Bowl, and 4 parallel environments.

Adaptive agent

The adaptive agent is the main model of the project. Unlike the PoC, it receives degraded RGB observations and must learn when to use the SENSE action. The adaptive agent therefore solves two coupled problems: navigation and perceptual control. It must decide both where to move and when additional visual detail is useful.

The adaptive setup uses six AI2-THOR scenes: FloorPlan1 to FloorPlan6. The target object is sampled randomly from Mug and Bowl. Episodes last at most 100 steps. The agent uses the full action space, 224 × 224 observations, DINOv2-base, a one-layer LSTM with hidden size 512, and a target-object embedding of dimension 8.

The adaptive agent uses the same PPO hyperparameters as the PoC: learning rate \(10^{-4}\), discount factor \(\gamma = 0.99\), PPO clipping \(\epsilon = 0.1\), value coefficient 0.5, entropy coefficient 0.05, and 8 PPO epochs per update.

Policy optimization with PPO

We train the policy with Proximal Policy Optimization (PPO). At timestep \(t\), the recurrent policy receives the current observation \(o_t\) and the LSTM hidden state \(h_t\). It outputs a distribution over actions:

\[ \pi_\theta(a_t \mid o_t, h_t) \]

where \(\theta\) are the trainable policy parameters, \(a_t\) is the selected action, \(o_t\) is the current observation, and \(h_t\) is the recurrent hidden state.

PPO updates the policy using the clipped surrogate objective:

\[ L^{\mathrm{CLIP}}(\theta) = \mathbb{E}_t \left[ \min \left( r_t(\theta)\hat{A}_t, \operatorname{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t \right) \right] \]

with:

\[ r_t(\theta) = \frac{ \pi_\theta(a_t \mid o_t, h_t) }{ \pi_{\theta_{\mathrm{old}}}(a_t \mid o_t, h_t) }. \]

The ratio \(r_t(\theta)\) compares the probability of the selected action under the updated policy with the probability under the old policy that generated the rollout. The term \(\hat{A}_t\) is the advantage estimate: it measures whether action \(a_t\) was better or worse than expected. The clipping parameter \(\epsilon\) limits the size of policy updates. In our experiments, \(\epsilon = 0.1\).

We compute advantages with Generalized Advantage Estimation (GAE). First, we compute the temporal-difference residual:

\[ \delta_t = r_t + \gamma V(o_{t+1}, h_{t+1}) - V(o_t, h_t) \]

Then the advantage estimate is:

\[ \hat{A}_t = \sum_{l=0}^{T-t-1} (\gamma \lambda)^l \delta_{t+l} \]

where \(V(o_t, h_t)\) is the critic value estimate, \(\gamma\) is the discount factor, and \(\lambda\) controls the bias-variance trade-off of the advantage estimate. We use \(\gamma = 0.99\). The PPO implementation uses \(\lambda = 0.95\).

The final optimization objective combines the policy loss, the value loss, and an entropy bonus:

\[ L(\theta) = L^{\mathrm{policy}}(\theta) + c_v L^{\mathrm{value}}(\theta) - c_e H(\pi_\theta) \]

where \(L^{\mathrm{value}}\) trains the critic to predict future return, \(H(\pi_\theta)\) is the entropy of the action distribution, \(c_v\) is the value-loss coefficient, and \(c_e\) is the entropy coefficient. The entropy term encourages exploration by preventing the policy from becoming deterministic too early. In our setup, \(c_v = 0.5\) and \(c_e = 0.05\).

Training stabilization

Early training runs showed that the agents were not learning useful navigation behavior. Rewards stayed low, success rates remained close to zero, and the policy did not develop a meaningful sensing strategy. To make training more stable, we progressively modified both the environment and the PPO training pipeline.

First, we moved from single-environment rollouts to parallel environment collection. Instead of updating PPO from one AI2-THOR episode at a time, we collect trajectories from several environments before each update. This reduces the variance of the training signal and gives PPO a more diverse batch of transitions.

We also made the PPO update more robust. Generalized Advantage Estimation is computed separately for each rollout, advantages are normalized jointly across the full batch, value clipping is used to stabilize critic learning, and recurrent hidden states are handled carefully so that the LSTM memory remains consistent within each episode.

Another important change was curriculum learning. Instead of always starting from the full task difficulty, we first expose the agent to easier episodes. The agent starts closer to the target object, then the initial distance is gradually increased. This helps the policy first learn simple navigation behavior before being exposed to harder exploration problems.

We also use a curriculum for perception. At the beginning of training, the agent starts with a relatively high visual resolution and a larger sensing budget. As training progresses, the observations become more degraded and the sensing budget becomes more constrained:

We also replaced Euclidean distance with geodesic distance for reward shaping and target-distance computation. This is important in indoor environments: if a wall separates the agent from the object, Euclidean distance can be misleading, while geodesic distance reflects the actual shortest navigable path.

Finally, we improved the policy inputs. Auxiliary features such as position and sensing budget are normalized to keep them on a stable scale. Orientation is encoded with sine and cosine values instead of raw angles, avoiding discontinuities around 360 degrees. We also added explicit target conditioning: the target object is represented by a learned embedding rather than by a fixed hash-based vector. This lets the policy know which object it is supposed to find.

Baselines

To evaluate whether adaptive resolution is useful, we compare the adaptive PPO agent against several baselines. These baselines are trained under the same general navigation setup but differ in how they use visual resolution.

  • High-resolution baseline: the agent always receives full-resolution observations and does not use SENSE.
  • Adaptive PPO agent: the agent learns when to use SENSE from interaction with the environment.

Evaluation metrics

We evaluate the agents along two axes: task performance and perception efficiency. Task-performance metrics measure whether the agent solves the navigation problem. We report cumulative reward, success rate, episode length, distance-to-goal reduction, and Success weighted by Path Length (SPL).

SPL is defined as:

\[ \mathrm{SPL} = S \cdot \frac{L^\star}{\max(L, L^\star)} \]

where \(S\) is 1 if the episode is successful and 0 otherwise, \(L^\star\) is the shortest path length to the target, and \(L\) is the path length actually traveled by the agent. SPL rewards agents that reach the target efficiently.

Perception-efficiency metrics measure how much high-resolution information the agent uses. We report the number of SENSE actions, the remaining sensing budget, the final resolution level, and the total sensing cost. These metrics test whether the adaptive agent can approach the performance of the high-resolution baseline while using fewer high-resolution observations.

Finally, we analyze the learned sensing behavior. We study whether the agent tends to sense early in the episode, after rotations, near the target, before DONE, or when the remaining budget is high. This helps determine whether the agent has learned a meaningful adaptive perception strategy rather than using high-resolution observations randomly.
